# Kernel image permissions in the single Ring-0 address space

The kernel uses one four-level address space. Its permanent root has no lower-half entries. Runtime code executes through the linked image at its existing image offset. Descriptor-selected RAM uses the direct-map reservation `[0xffff800000000000, 0xffffc00000000000)`. Managed device and firmware views use the existing owned window at `0xffffd00000000000`; the separate TLB test windows retain their bounded test-only role.

An immutable linker-derived physical-content plan controls both image aliases before the BSP activates the root. Runtime text is read-only and executable through the linked alias, and read-only and nonexecuting through the direct alias. Read-only data, MSR recovery records and the original trampoline blob are read-only and nonexecuting through both aliases. Mutable data, BSS, descriptor storage and the high 16-KiB BSP stack are writable and nonexecuting. Unowned padding in image reservations is conservatively read-only and nonexecuting. Compatible rodata/fixup or data/BSS page sharing is permitted; conflicting permissions on one page are rejected.

The retained physical boot sections are distinct from the high linked interval. The accepted `.boot_data` section is reserved physical bootstrap storage rather than an ELF LOAD segment. Its static entry tables and transient stack stay reserved. Its direct view is writable data and nonexecuting; the retained boot-code direct view is read-only and nonexecuting. The main root adds no executable boot alias.

The builder fills unpublished tables using typed entries. Shared image ancestors allow the union of child rights; leaves impose the specific section restrictions. The independent preactivation checker and whole-main-root walker compute effective write access as the AND of all controlling R/W bits and execution denial as the OR of NX bits. Both verify physical identity and complete coverage in addition to permissions. The postactivation table hashes and high owner readback remain in place. There is no runtime image-permission API.

All data mapping constructors preserve supported NX from creation: RAM, heap, task/AP/IST stacks, DMA CPU views, owned MMIO/framebuffer, read-only WB firmware and scratch views. Image and boot backing cannot be admitted as a new owned device or scratch alias. Device cache selection and discovery authority are unchanged. The framebuffer claim remains PAT-selected WC; its full effective memory type is not computed.

With NX available, the permanent main root contains no effective writable/executable leaf. With NX absent, the kernel keeps CR0.WP and read-only image aliases, leaves every NX bit clear and reports execute protection and strict W^X capability unavailable. It does not execute the data-denial probes on that profile. This is a capability limitation, not a zero-RWX result.

The transient entry root and private AP bootstrap root have separate lifetimes. The original linked trampoline is copied as RO/NX data. Its distinct owned low destination must remain executable and writable in the single-page private bootstrap mapping until all intended APs have entered their high descriptor/stack state and locally read back the main CR3. The existing four private table pages are then retired once; shared high tables and seven static entry pages are retained. This bounded boot-only RWX use is not a permanent-root exception.

SELFTEST adds fixed assembler stores to text and rodata through each alias, and fixed indirect calls into a harmless initialized RET byte sequence in writable data. Each actual online CPU executes six attempts with NX, or four real write attempts and two explicit unsupported fetch results without NX. Recovery matches the exact active generation, CPU/APIC, physical root, target/site, supervisor CS, CR2 and protection error (write 3, instruction fetch 17). The fetch recovery consumes the call's real return address. The handler disarms and records bounded facts before the acknowledged request completes. Unexpected access is a test failure; unrelated faults still panic. Production contains the enforcement and ordinary low-address fault diagnosis but no protection target, recovery command or test request operation.

Full raw leaf runs are observed at device readiness/workload boundaries and while each TLB scratch window is live, before priming/concurrent work. A separate stopped physical-memory capture independently reconstructs the main tree and the pre/post AP bootstrap lifecycle. Debugger observations are outside functional timing and do not modify guest mappings or registers.

These protections detect kernel bugs and limit accidental writes or execution. They do not isolate malicious fully privileged Ring-0 code capable of changing paging or control registers. No user address spaces, DMA sandbox, IOMMU, KASLR, SMEP/SMAP, stack guards or executable heap are introduced. NULL accesses remain genuine nonpresent faults with the accepted exact test-only recovery. Hardware validation, human visual review, stack guards and later interrupt-latency work remain separate.
