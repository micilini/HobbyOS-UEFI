## Focused review representation

`physical-translation-review.py` begins with current accepted series, candidates,
fixed native selection, required negatives and specific baseline identities.
It follows explicit current receipt dependencies. It never selects a session
root, all development attempts or retired campaign trees. Original local
attempts, full images and previous archives remain intact and indexed locally.
Failed attempts relevant to the current chronology retain their raw causal
outputs. Omitted retired campaigns are not labeled portably replayed.
The local retention index records their original candidate identity, outcome
and retirement receipt. A selection audit rejects whole historical/development
roots and any inferred dependency without its consuming current receipt.
The review tool's `--preview --selection-audit-only` mode checks this dependency
closure without claiming semantic acceptance and cannot create a delivery ZIP.
The requirement-inventory transport alias references the exact versioned source
bytes whose digest was frozen in the collected ledger.
For the three preserved paging comparisons, only the eighteen original serial
and timestamp streams, bound launch/candidate receipts and baseline summaries
are retained. They are copied byte-for-byte from the reviewed archives. The
same timing parser reconstructs each sample and median; replay of this subset
does not claim replay of an entire retired runtime campaign.

Current source is complete and directly readable. Prior sources are exact
manifests plus content references, primarily to unchanged current files. Raw
evidence uses SHA-256 addressed one-MiB chunks or whole current-source references.
Each chunk uses bounded zlib encoding, avoiding another multi-GiB local staging
copy. Decoded size, stream termination and both stored/decoded hashes are checked.
Identical files and shared cumulative prefixes therefore travel once. Logical
paths, original bytes, declared canonical modes, order, timestamps and hashes
reconstruct exactly.
Source retention receipts may record local `0664`/`0775` permissions. Their Git
executable identity reconstructs as literal `0644`/`0755`, and the verifier
reproduces the original Git tree; it does not claim local permission equality.
Native synthetic fixtures retain their exact deltas/recipes and rejecting
boundaries. Full binary images stay local; bounded ELF/table facts are explicit
offline substitutions, not a claim to execute or rehash omitted binaries.

The materializer validates every input before creating a new external scratch
directory. It rejects traversal, symlinks, unknown types, conflicting or duplicate
paths, missing/unlisted blobs, hash substitution and mode mismatch. Limits are
one GiB per logical file, 16 GiB aggregate evidence, 100000 files and 200000
chunk references. ZIP admission also limits declared extracted payload to two
GiB before CRC expansion; reconstruction checks actual free scratch space plus
a 64-MiB reserve before writing. These resource bounds do not substitute for
the 100-MiB compressed delivery target. Large streams are reconstructed incrementally. Native and
semantic validators run on exact materialized bytes, never on hash agreement
alone. Originals are rechecked after replay.

`package-size-report.json` separates unique payload from reconstructed logical
bytes and reports groups, largest objects, duplicate savings, ZIP overhead and
the 100-MiB target. Whole-file savings overlap chunk savings and are never added.
Any excess requires a concrete consuming-validator dependency explanation.
Small size cannot excuse missing evidence or wholesale-history selection.
